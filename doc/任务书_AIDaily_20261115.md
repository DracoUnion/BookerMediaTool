# 任务书：在 `BookerMarkdownTool` 中新增子命令 `aidaily`

## 0. 读者与任务概述

你需要在现有 `BookerMarkdownTool` 包内新增一个子命令 `aidaily`，实现“AI平权日报”功能：从固定信源采集、粗筛、去重、LLM 精筛、渲染简报。**必须严格遵守本文档第 3 节列出的现有项目约定**，不得另起独立 CLI，不得引入与项目风格冲突的持久化方案（如 PostgreSQL、独立 SQLite 文件），不得自行定义全局参数。

阅读本文档前，请先阅读 `BookerMarkdownTool/AGENTS.md` 与 `BookerMarkdownTool/BookerMarkdownTool/__main__.py`，理解现有子命令的注册方式与公共参数机制。

---

## 1. 功能定位（沿用前序设计，不重复展开）

`aidaily` 是以“算力与模型能力下沉、普惠”为编辑视角的定向监测子命令。四个主题分类标识符固定：

| 标识符 | 中文名 |
|---|---|
| `compression` | 模型压缩 |
| `weight_edit` | 权重操控 |
| `edge` | 端侧与消费级推理 |
| `low_resource` | 低资源训练 |

六类信源标识符固定：`arxiv`、`hn`、`tds`、`machine_heart`、`quantumbit`、`xinzhiyuan`。

**与之前版本的差异**（因整合进本项目）：

- 不再提供独立子命令 `aiqdaily`，改为 `md-tool aidaily`。
- 不再使用配置文件；所有参数走 argparse。
- **LLM 参数复用项目已有的公共参数**（`-m/--model`、`-k/--key`、`-H/--host`、`-tm/--temp`、`-retry`、`--emb`），aidaily **不得**重新定义 `-m`、`-k`、`-H`、`-tm`、`--retry`。
- 不再使用 SQLite/sqlite-vec；去重索引与缓存在 `{out_dir}` 下的普通文件中维护（见 §6）。
- 阶段切换通过 `--stage` 参数完成，而非拆成多个子命令。

---

## 2. 硬性约束

1. **单子命令**：`aidaily` 是一个子命令，通过 `--stage {all,collect,filter,dedup,enrich,render,stats}` 控制只跑某一阶段，默认 `all`。
2. **所有参数从命令行传入并有默认值**。`--help` 必须通过 `argparse.ArgumentDefaultsHelpFormatter` 展示所有默认值。
3. **幂等与可重跑**：同日期重复跑不产生重复简报、不重复调用 LLM；任一阶段失败后，可用 `--stage <阶段>` 单独重跑。
4. **中间产物落盘**：每阶段产物写入 `{out_dir}/{run_date}/`（见 §6）。
5. **无 TTY 交互**：禁止 `input()`、进度条。crontab 无人值守。
6. **LLM 只通过项目的 `openai.py` 中的 `OpenAIClient` 调用**（`call_llm_retry`），不新增 LLM SDK 依赖。
7. **日志走项目 `logging` 约定**（与 `openai.py` 里的 `logger` 同级），不另建 handler；crontab 场景由外部重定向。
8. **不得改动 `util.py`、`openai.py` 现有公开接口**；如确需新增通用函数，加到 `util.py` 且保持向后兼容。

## 3. 模块结构与项目约定（必须遵循）

按 `AGENTS.md` 的命名约定（`sub_cmd` → `sub_cmd`，一个连字符组），`aidaily` 属于**编排器 + 智能体模式**（有复杂多步工作流 + LLM 调用）。新建四个文件：

```
BookerMarkdownTool/BookerMarkdownTool/
├── aidaily.py          # 编排器 + 入口 + 子命令注册
├── aidaily_agent.py    # 智能体（LLM 调用）
├── aidaily_pmt.py      # 提示词模板
└── aidaily_models.py   # Pydantic 模型
```

在 `__main__.py` 中按现有方式注册（在遍历各模块注册处，追加 `from . import aidaily; aidaily.reg_subparser(subparsers)`）。

### 3.1 `aidaily.py`

- 定义 `AidailyOrchestrator` 类；每个工作流步骤实现为 `step_xxx(self)` 方法：
  - `step_collect()` — 采集
  - `step_filter()` — 粗筛
  - `step_dedup()` — 两级去重
  - `step_enrich()` — LLM 精筛
  - `step_render()` — 渲染简报
- `run(self)` 根据 `args.stage` 分派：`all` 依次执行 5 步，其余执行对应单步；`stats` 走 `print_stats(self)`。
- 入口 `aidaily_hdl(args)` 实例化 `AidailyOrchestrator(args)` 并调 `run()`。
- `reg_subparser(subparsers)`：用 `parents=[llm_parser]`（项目已有的 LLM 公共参数父解析器；若项目未用 `parents` 机制，则按 `__main__.py` 的现有方式附加参数）注册 `aidaily` 子命令，设置 `func=aidaily_hdl`、`formatter_class=argparse.ArgumentDefaultsHelpFormatter`。

### 3.2 `aidaily_agent.py`

- 定义 `AidailyAgent` 类，构造时接收 `args`。
- 方法：`enrich_one(self, article: Article) -> Enrichment`，内部：
  - 构造 `msgs`（system + user），user 部分由 `util.render_prompt(AIDAILY_ENRICH_USER_PMT, source=..., title=..., summary=..., url=..., hint=...)` 渲染；
  - 调用 `self.client.call_llm_retry(msgs, args.model, retry=args.retry, temp=args.temp, parse_output=self._parse_enrichment)`；
  - `_parse_enrichment(text)` 用 `util.ext_code_block` 取出三反引号块，`json.loads` + `parse_obj_as(Enrichment, ...)`；失败抛异常以触发重试。
- `AidailyAgent.__init__` 里通过项目的 `OpenAIClient.from_args(args)` 构造客户端（或复用 `__main__.py` 已有的构造方式），**不要**自己调 `openai.OpenAI`。
- 并发由编排器 `step_enrich` 用 `concurrent.futures.ThreadPoolExecutor(max_workers=args.llm_max_concurrency)` 调度，每个 worker 调 `agent.enrich_one(article)`；worker 内部捕获异常后记录失败计数并继续，`KeyboardInterrupt` 向上抛。

### 3.3 `aidaily_pmt.py`

- `AIDAILY_ENRICH_SYS_PMT`：中文 system prompt，明确定位为“AI平权日报”编辑，列出四个分类标识符及含义，列出 `resource_signal` 允许取值（`a100_80g` / `consumer_24g` / `consumer_16g` / `cpu` / `colab` / `single_gpu` / `unspecified`），要求只输出 JSON（用三反引号包裹）。
- `AIDAILY_ENRICH_USER_PMT`：带 `{source}`、`{title}`、`{summary}`、`{url}`、`{hint}` 占位符；`hint` 由编排器按 `source` 分支给出（arxiv 侧重资源条件、hn 侧重部署经验、tds 侧重硬件与可复现性、中文媒体侧重开源工具与消费硬件适配）。
- `prompt_version` 由 `util.md5(AIDAILY_ENRICH_SYS_PMT + AIDAILY_ENRICH_USER_PMT)` 生成，供缓存键使用。

### 3.4 `aidaily_models.py`

```python
from typing import Literal, List
from pydantic import BaseModel, Field

Category = Literal["compression", "weight_edit", "edge", "low_resource"]
ResourceSignal = Literal[
    "a100_80g","consumer_24g","consumer_16g","cpu","colab","single_gpu","unspecified"
]

class Article(BaseModel):
    id: str
    source: str
    url: str
    title: str
    summary: str = ""
    published_at: str
    lang: str
    run_date: str

class DedupedArticle(Article):
    is_primary: bool = True
    evidence_for: str = ""
    evidence: List[dict] = Field(default_factory=list)

class Enrichment(BaseModel):
    relevance: float = Field(ge=0, le=1)
    categories: List[Category]
    one_liner: str
    resource_signal: ResourceSignal

class EnrichedArticle(DedupedArticle):
    enrichment: Enrichment

class RunStatus(BaseModel):
    run_date: str
    started_at: str
    finished_at: str = ""
    status: Literal["running","success","degraded","failed"] = "running"
    exit_code: int = 0
    source_status: dict = Field(default_factory=dict)
    counts: dict = Field(default_factory=dict)
    cli_args: dict = Field(default_factory=dict)
```

字段名固定；`run_date`、`run_date` 中的日期格式统一 `YYYY-MM-DD`。

## 4. 参数设计

### 4.1 复用项目公共参数（不重复定义）

`-m/--model`、`-k/--key`、`-H/--host`、`-tm/--temp`、`-retry`、`--emb` 由 `__main__.py` 提供，aidaily 通过 `args` 直接读取。**不要**在本子命令里再定义这些参数名。

### 4.2 aidaily 自有参数

全部为可选参数，均有默认值。放在 `reg_subparser` 里注册。

**运行控制**

| 参数 | 默认值 | 说明 |
|---|---|---|
| `--stage` | `all` | `all`/`collect`/`filter`/`dedup`/`enrich`/`render`/`stats` |
| `--date` | 今天（本地时区） | 目标日期 `YYYY-MM-DD` |
| `--since` | 空 | 自定义窗口起点（与 `--until` 成对） |
| `--until` | 空 | 自定义窗口终点 |
| `--out-dir` | `./ai_daily_out` | 产物与索引根目录 |
| `--window-hours` | `24` | 采集窗口 |
| `--lookback-days` | `7` | 跨日去重回看天数 |
| `--force` | `False` | 忽略“当日已完成”标记 |
| `--dry-run` | `False` | 只打印计划，不联网、不调 LLM、不写文件 |
| `--resume` | `False` | 仅 `enrich` 阶段有意义：跳过已缓存条目 |
| `-v/--verbose` | `False` | DEBUG 日志 |

**信源**

| 参数 | 默认值 |
|---|---|
| `--sources` | `arxiv,hn,tds,machine_heart,quantumbit` |
| `--arxiv-categories` | `cs.LG,cs.CL,cs.AI` |
| `--hn-min-points` | `5` |
| `--tds-feed` | `https://towardsdatascience.com/feed` |
| `--machine-heart-feed` | 实现者提供可用 URL 作为默认 |
| `--quantumbit-feed` | 实现者提供可用 URL 作为默认 |
| `--xinzhiyuan-feed` | `""`（空，跳过该信源） |

**主题词**（逗号分隔字符串；传入即完全覆盖默认）

| 参数 | 默认值 |
|---|---|
| `--compression-keywords` | `quantization,low-bit,int4,gptq,awq,pruning,sparsity,distillation` |
| `--weight-edit-keywords` | `knowledge editing,model editing,weight editing,model merging` |
| `--edge-keywords` | `on-device,edge inference,consumer gpu,llama.cpp,local inference,gguf` |
| `--low-resource-keywords` | `mezo,zeroth-order,memory-efficient fine-tuning,low-resource training,single gpu` |
| `--tds-extra-keywords` | `tutorial,hands-on,guide,colab,low-cost,budget,peft,lora` |
| `--blacklist` | `funding,acquisition,ceo,layoff,融资,裁员` |

**去重**

| 参数 | 默认值 |
|---|---|
| `--simhash-max-distance` | `3` |
| `--semantic-threshold` | `0.85` |
| `--hot-window-boost` | `0.80` |
| `--hot-window-count` | `200` |

**LLM（新增，不与公共参数冲突）**

| 参数 | 默认值 | 说明 |
|---|---|---|
| `--llm-max-concurrency` | `4` | enrich 阶段线程池大小 |
| `--llm-no-cache` | `False` | 关闭缓存 |
| `--llm-max-tokens` | `512` | 传给 `call_llm_retry(max_tokens=...)` |

### 4.3 参数校验

- `--since` 与 `--until` 必须成对出现，否则 `parser.error(...)`（argparse 自动退出 2）。
- `--window-hours <= 0`、`--simhash-max-distance` 不在 `[0,64]`、`--semantic-threshold` 不在 `(0,1]`、`--sources` 含未知标识符 → `parser.error(...)`。
- `--sources` 含 `xinzhiyuan` 但 `--xinzhiyuan-feed` 为空 → 日志警告并跳过，不算失败。
- `--stage ∈ {enrich, all}` 且 `--key` 与 `OPENAI_API_KEY` 均为空 → 日志报错并 `sys.exit(2)`。`--dry-run` 豁免此检查。
- `--emb` 未提供且 `EMB_MODEL_PATH` 未设置 → 跳过语义去重，仅 SimHash，日志警告；不视为失败。

## 5. 各阶段实现规格

### 5.1 `step_collect`

- 窗口 `[since, until)`，默认 `until = 运行时刻`，`since = until - window_hours`（时区按本机 `datetime.now().astimezone()`）。
- `id = md5(source + url + title)[:16]`，与项目 `util.md5` 复用。
- 信源采集：
  - `arxiv`：RSS `https://rss.arxiv.org/rss/{cat}`（`feedparser`），按 `--arxiv-categories` 每个分类拉；同时可调 arXiv API 按主题词补充，同一 `id` 去重。
  - `hn`：`requests` 调 Algolia，按每个英文主题词查一次，`numericFilters=created_at_i>{ts},points>{hn_min_points}`。
  - `tds`/`machine_heart`/`quantumbit`/`xinzhiyuan`：`feedparser` 拉 `--*-feed`，按 `published` 过滤窗口。
- 单信源使用 `requests.get(..., timeout=30)`；异常捕获后写入 `RunStatus.source_status[source] = "failed"`，继续。
- 结果写 `{out_dir}/{run_date}/raw.yaml`（`util.write_yaml_model`，`List[Article]`），并 append 到 `{out_dir}/.index/articles.json`（见 §6.2）。

### 5.2 `step_filter`

- 读 `raw.yaml`，按 §7.2 规则粗筛，写 `filtered.yaml`。
- 规则：
  1. 标题或摘要命中 `--blacklist` → 丢弃；
  2. 合并四类主题词，标题+摘要大小写不敏感子串匹配；
  3. `source == tds` 额外匹配 `--tds-extra-keywords`，命中任一即通过；
  4. 其他来源必须命中至少一个主题词；
  5. HN 条目 URL 属于 `github.com`/`arxiv.org`/`huggingface.co` 时保留（作为可选加分项）。

### 5.3 `step_dedup`

**第一级 SimHash**：

- 对 `title + " " + summary` 归一化：小写、去标点；中文按字符 3-gram、英文按空格分词。
- 64 位 SimHash；与 `{out_dir}/.index/simhash.json` 中 `lookback_days` 天内条目比对，汉明距离 ≤ `--simhash-max-distance` 判重。

**第二级语义去重**（仅在 `--emb` 或 `EMB_MODEL_PATH` 可用时启用）：

- 对 `title + " " + summary[:512]` 编码；与 `{out_dir}/.index/embeddings.npz` 中 `lookback_days` 内条目做余弦相似度。
- 阈值：当日 `filtered` 条目数 > `--hot-window-count` 时用 `--hot-window-boost`，否则用 `--semantic-threshold`。
- **必须启用跨语言比对**（中英向量可比）。

**合并策略**：信源优先级 `arxiv > tds > hn > machine_heart > quantumbit > xinzhiyuan`；高优先级为主条目，其余作为 evidence 附在 `DedupedArticle.evidence`。

写 `deduped.yaml`，并更新索引文件。

### 5.4 `step_enrich`

- 读 `deduped.yaml`，对每条并发调用 `AidailyAgent.enrich_one`。
- **缓存**：缓存键 `md5(article.id + prompt_version + args.model + args.host)`；命中 `{out_dir}/.cache/enrich/{key}.yaml` 时直接 `util.read_yaml_model` 读出并跳过 API。`--llm-no-cache` 关闭。
- 后处理：
  - `relevance == 0` → 不入 `enriched.yaml`；
  - `0 < relevance < 0.3` → 保留但标注“观察”；
  - `relevance >= 0.7` → 正式条目。
- 写 `enriched.yaml`（`List[EnrichedArticle]`）；失败条目数写入 `RunStatus.counts.enrich_failed`。

### 5.5 `step_render`

- 读 `enriched.yaml`，按 `resource_signal` 与 `relevance` 组织，写：
  - `{out_dir}/{run_date}/digest.md`
  - `{out_dir}/{run_date}/digest.html`（单文件内嵌 CSS）
  - `{out_dir}/{run_date}/digest.json`（结构化：`date`、`stats`、`categories`、`observations`）
- Markdown 结构：

```markdown
# AI平权日报 · YYYY-MM-DD

> 统计：采集 N 条 → 粗筛 M 条 → 去重 K 条 → 入选 J 条

## 模型压缩
- **标题**（信源 · 相关度 高/中）
  一句话要点。
  资源信号：消费级 24G ｜ 佐证：量子位、HN
  [链接](url)
...
## 观察区（相关度 < 0.3）
...
```

- `resource_signal ∈ {consumer_24g, consumer_16g, colab, cpu}` 的条目标题后加 `🟢`。
- 同一 `run_date` 重复 render **覆盖**而非追加。

### 5.6 `--stage stats`

- 读 `{out_dir}/{run_date}/run.json` 与 `{out_dir}/.cache/enrich/` 目录：
  - 各阶段条目数；
  - 信源分布；
  - LLM 实际调用数与缓存命中数（对比 `enriched` 条目数）；
  - `filter/raw` 比例（用于调参，目标 10%–20%）。
- 打印到 stdout，同时写出 `{out_dir}/{run_date}/stats.txt`。

## 6. 数据落盘格式

### 6.1 每日产物目录

```
{out_dir}/{run_date}/
├── raw.yaml
├── filtered.yaml
├── deduped.yaml
├── enriched.yaml
├── digest.md
├── digest.html
├── digest.json
├── run.json
└── stats.txt         # 仅 --stage stats 时生成
```

所有 `*.yaml` 用 `util.write_yaml_model` / `util.read_yaml_model` 读写（列表用 `parse_obj_as(List[XxxModel], ...)`）。`run.json` 用 `json.dumps` 直接写（为便于人类阅读，不用 YAML）。

### 6.2 跨日索引

```
{out_dir}/.index/
├── articles.json     # {article_id: {source, title, published_at, run_date}}
├── simhash.json      # {article_id: int64}
└── embeddings.npz    # np.savez: ids=[...], vectors=ndarray[N,384]
```

- 每次 `dedup` 阶段后，把当日新条目 append 到索引，并清理 `published_at` 早于 `run_date - lookback_days` 的条目。
- 索引读写用 `json.loads/dumps` + `numpy.savez/load`；不引入 sqlite。

### 6.3 LLM 缓存

```
{out_dir}/.cache/enrich/{md5key}.yaml    # 内容为 Enrichment 模型
```

- 缓存键组成：`md5(article_id + prompt_version + model + host)`。
- README 说明：手动删除 `.cache/enrich/` 即可重置缓存。

### 6.4 并发锁

- 锁文件 `{out_dir}/.index/.lock`；用 `fcntl.flock(..., LOCK_EX | LOCK_NB)` 在 `run()` 开头加锁、结束时释放。
- 锁冲突时打印一行提示并以 **退出码 5** 退出。

---

## 7. 退出码

| 码 | 含义 |
|---|---|
| 0 | 成功 |
| 1 | 通用错误 |
| 2 | 参数错误（通过 `parser.error` 或 `sys.exit(2)`） |
| 3 | 部分信源采集失败但产物已生成 |
| 4 | LLM 调用失败（enrich 未完成，可用 `--stage enrich --resume` 续跑） |
| 5 | 锁冲突 |

`run()` 汇总各阶段：只要生成了 `digest.md` 即视为“至少降级成功”；同时若有信源失败则返回 3；若有 enrich 失败且 `enriched.yaml` 条目数 < `deduped.yaml` 条目数，返回 4。多个码并存时取最大值，避免掩盖严重问题（`5 > 4 > 3 > 1 > 0`）。

`sys.exit(code)` 由 `aidaily_hdl` 统一负责；`__main__.py` 不改动。

## 9. 部署与 crontab

**不新增脚本文件**；README 中给出示例：

```bash
# crontab 行
0 8 * * * cd /path/to/repo && \
  md-tool aidaily --stage all \
    -m gpt-4o-mini -H https://api.openai.com/v1 \
    -k "$OPENAI_API_KEY" \
    --out-dir "$HOME/ai_daily_out" \
    >> "$HOME/ai_daily_out/cron.log" 2>&1
```

**注意**（写入 README）：

- crontab 的 `PATH` 与登录 shell 不同，需显式包含 `md-tool` 所在目录。
- 密钥仅通过环境变量 `OPENAI_API_KEY` 或 `-k` 传入；不要在 crontab 行里硬编码明文 `-k sk-...`。推荐写 `-k "$OPENAI_API_KEY"`，并在 crontab 文件顶部 `OPENAI_API_KEY=...`（crontab 支持变量赋值）。
- `cd` 到仓库路径或用绝对路径调用，因为 `--out-dir` 默认值是相对路径 `./ai_daily_out`。

## 10. 验收标准

**A. 集成与注册**

1. `md-tool --help` 的子命令列表包含 `aidaily`；`md-tool aidaily --help` 显示全部参数与默认值。
2. `md-tool aidaily --stage stats` 在无数据时打印空统计并退出 0。
3. 与现有子命令（如 `md2skill`、`clean-heading`）共存，互不干扰；`md-tool -m xxx aidaily ...` 与 `md-tool aidaily -m xxx ...` 均可正常识别 `-m`（验证 `parents` 附加方式正确）。

**B. 幂等与可重跑**

4. `md-tool aidaily --date 2026-11-15 --stage all` 成功后再跑一次，退出 0，`digest.md` 内容不变，`run.json.status` 无新增 success 记录。
5. 删除 `digest.md` 后 `md-tool aidaily --date 2026-11-15 --stage render`，文件重新生成且 LLM 实际调用数为 0（`stats` 显示缓存命中数不变）。
6. 用错误的 `-H` 让 `enrich` 失败，`run` 返回 4；恢复后用 `--stage enrich --resume` 成功，已缓存条目不再请求 API。

**C. 去重**

7. Fixture：同一 arXiv 论文英文条目 + 中文编译条目，`dedup` 后剩 1 条主条目，中文作为 evidence。
8. Fixture：两条相同 HN 转载（不同 url），SimHash 判重后剩 1 条。
9. Fixture：`lookback_days` 前已入库论文今日再出现，不重复进入简报。

**D. 过滤与分类**

10. Fixture：标题含 `quantization` 但内容为量子物理，enrich 后 `relevance=0`，不进入简报。
11. Fixture：TDS 教程标题不含主题词但含 `hands-on` 和 `Colab`，filter 通过并归入 `low_resource` 或 `edge`。
12. Fixture：黑名单词出现在标题，filter 阶段丢弃。

**E. 输出**

13. `digest.md` 含四个分类标题、观察区、统计行；`consumer_24g` 条目带 `🟢`。
14. `digest.json` 可被 `json.load` 解析；`stats` 字段与 `run.json.counts` 一致。

**F. 运行环境与参数**

15. 无 TTY 环境下（`</dev/null`）执行 `--stage all` 不阻塞、不报 TTY 错误。
16. 同时启动两个 `--stage all`，第二个立即返回 5。
17. 未设置 `OPENAI_API_KEY` 且未传 `-k`，`--stage enrich` 返回 2 且不发请求；`--stage enrich --dry-run` 返回 0。
18. 传 `--sources arxiv` 只采集 arXiv，`run.json.source_status` 中其他信源为 `skipped`。
19. 传非法参数（如 `--simhash-max-distance 99`）返回 2，`--help` 中可见默认值与合法取值范围说明。

**G. LLM 层**

20. 用 `responses` 或 `httpx.MockTransport` 模拟 `-H` 指定的接口：
    - 合法 JSON（三反引号包裹）→ `Enrichment` 解析通过；
    - 非法 JSON → 触发 `call_llm_retry` 重试；
    - 重试耗尽 → `enrich` 返回 4，`enriched.yaml` 保留成功条目；
    - 缓存命中 → 不发起 HTTP 请求。

**H. 性能基线**

21. 默认五信源、过去 24 小时约 200–500 条 raw，单次 `--stage all` 在普通笔记本上 ≤ 10 分钟（不含首次嵌入模型下载）。

## 13. 实施顺序建议

| 阶段 | 内容 | 完成标志 |
|---|---|---|
| 1 | `aidaily_models.py` + `aidaily_pmt.py` + `aidaily.py` 骨架（含 `reg_subparser`、`--stage stats` 空实现、锁） + 在 `__main__.py` 注册 | `md-tool aidaily --help` 可见全部参数；`--stage stats` 空数据返回 0；锁冲突返回 5（A1、A2、F16） |
| 2 | `step_collect` + `step_filter` + `--dry-run` | `raw.yaml`/`filtered.yaml` 生成，`--dry-run` 返回 0 且不联网（F18、F17 dry-run 分支） |

**优先级**：阶段 1–2 的注册与参数、阶段 6 的锁与退出码必须最先确定——在 crontab 无人值守场景下，参数正确、幂等、退出码正确比 LLM 分类精度更重要。分类精度可通过 prompt 迭代，但前者出错会让整个定时任务失效。
